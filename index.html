Section 01

Qu'est-ce que le Machine Learning ?

Le Machine Learning est une branche de l'Intelligence Artificielle qui permet à une machine d'apprendre à partir de données sans être explicitement programmée pour chaque tâche.

La hiérarchie IA → ML → Deep Learning

Intelligence Artificielle
Science & ingénierie des machines intelligentes

Inclut les règles expertes, la logique, et le ML. Ex : chatbots.

Machine Learning
Apprendre sans programmation explicite

Sous-domaine de l'IA. Ex : spam filter, recommandations.

Deep Learning
Apprentissage par réseaux de neurones profonds

Sous-domaine du ML. Ex : reconnaissance d'images, GPT.

Définition formelle (Tom Mitchell, 1998)

Cadre T–E–P Un programme apprend de l'expérience E pour la tâche T et la mesure P si ses performances sur T mesurées par P s'améliorent avec E. Exemple — Filtre anti-spam : T = classer un e-mail en spam ou non-spam E = collection de milliers d'e-mails déjà classifiés P = exactitude (% de décisions correctes) sur de nouveaux e-mails

Les trois grandes familles d'apprentissage

Supervisé
( X, y )

Données étiquetées. Chaque exemple a une réponse connue. → Régression, Classification.

Non supervisé
( X )

Pas de labels. La machine découvre des structures. → Clustering, réduction de dimension.

Par renforcement
r(s, a)

Apprend par récompenses/punitions. → Jeux, robotique, voitures autonomes.

Pourquoi le ML est devenu incontournable aujourd'hui

Trois facteurs expliquent l'explosion du ML depuis 2010 :

📊 Données massives

Internet, capteurs et smartphones génèrent des quantités colossales de données que les algorithmes peuvent exploiter.

⚡ Puissance GPU

Les processeurs graphiques (GPU) permettent de traiter des millions d'opérations en parallèle — 100× plus rapide qu'un CPU.

🧠 Algorithmes matures

Des décennies de recherche ont produit des algorithmes robustes : réseaux de neurones, arbres boostés, transformers.

Section 02

Régression linéaire simple: Le modèle

La régression linéaire simple modélise la relation entre une variable d'entrée x et une sortie numérique y par une droite. C'est le modèle le plus simple de l'apprentissage supervisé.

Équation du modèle

Hypothèse — régression linéaire simple ŷ = w · x + b ŷ = prédiction du modèle (valeur estimée) x = variable d'entrée (la feature) w = poids / pente — influence de x sur ŷ. Si w = 2.5 : +1m² → +2.5k€ b = biais — valeur de ŷ quand x = 0 (ordonnée à l'origine)
Processus d'apprentissage en 2 phases

Phase 1 — Entraînement : on cherche les valeurs de w et b qui minimisent l'erreur sur les données connues. Phase 2 — Prédiction : une fois w et b appris, on peut prédire y pour n'importe quel nouveau x en calculant simplement ŷ = wx + b.

Section 03

La fonction de coût J(w, b)

Pour mesurer la qualité d'un modèle, on a besoin d'une fonction de coût J qui quantifie l'écart total entre les prédictions ŷ et les vraies valeurs y. L'objectif est de trouver w et b qui minimisent J.

La MSE — Mean Squared Error

Erreur Quadratique Moyenne (MSE) J(w, b) = 1/(2m) · Σᵢ₌₁ᵐ ( wx⁽ⁱ⁾ + b − y⁽ⁱ⁾ )² m = nombre d'exemples d'entraînement Le facteur 1/2 simplifie les calculs lors de la dérivation (le 2 se simplifie) L'erreur est au carré pour : éviter les annulations +/−, pénaliser les grosses erreurs
Propriété clé : J est convexe

J est une somme de fonctions convexes (carrés de fonctions affines) → J est convexe. Elle a donc un seul minimum global, aucun minimum local. La descente de gradient converge toujours vers ce minimum, quelle que soit l'initialisation.

Parabole J(w) — visualisation

La parabole confirme la convexité. Le point doré est le minimum global (w*, b*).

Section 04

Dérivées partielles de J

Le gradient de J nous dit dans quelle direction se déplacer pour faire descendre J. Il faut calculer ∂J/∂w et ∂J/∂b.

Calcul de ∂J/∂w — étape par étape

1
J(w,b) = (1/2m) · Σᵢ ( wx⁽ⁱ⁾ + b − y⁽ⁱ⁾ )²
2
On pose uᵢ = wx⁽ⁱ⁾ + b − y⁽ⁱ⁾ → d/dw[uᵢ²] = 2·uᵢ · ∂uᵢ/∂w
3
∂uᵢ/∂w = x⁽ⁱ⁾ (b et y⁽ⁱ⁾ sont constants par rapport à w)
4
(1/2m) · 2·Σᵢ uᵢ·x⁽ⁱ⁾ = (1/m) · Σᵢ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾) · x⁽ⁱ⁾

∂J/∂w = (1/m) · Σᵢ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾) · x⁽ⁱ⁾

Calcul de ∂J/∂b

1
Même démarche : ∂uᵢ/∂b = 1 (w·x⁽ⁱ⁾ et y⁽ⁱ⁾ sont constants par rapport à b)
2
(1/2m) · 2·Σᵢ uᵢ · 1 = (1/m) · Σᵢ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾)

∂J/∂b = (1/m) · Σᵢ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾)

Interprétation du signe du gradient

Que nous dit le gradient ? ∂J/∂w > 0 → J monte quand w augmente → il faut réduire w ∂J/∂w < 0 → J descend quand w augmente → il faut augmenter w ∂J/∂w = 0 → minimum local atteint pour w → convergé ✓
Calcul numérique — initialisation w=0, b=0 Calcul en cours...
Section 05

Algorithme de Descente de Gradient

La descente de gradient est la méthode itérative qui trouve w et b optimaux en se déplaçant toujours dans la direction qui fait descendre J le plus vite.

Analogie : imaginez-vous dans le brouillard sur une montagne. Vous voulez atteindre la vallée (le minimum de J). Vous sentez la pente sous vos pieds et faites toujours un pas dans la direction la plus raide vers le bas. En répétant ça, vous atteignez la vallée — c'est la descente de gradient.

Règle de mise à jour — SIMULTANÉE

Mise à jour simultanée à chaque itération w_temp = w − α · ∂J/∂w = w − α · (1/m) · Σᵢ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾) · x⁽ⁱ⁾ b_temp = b − α · ∂J/∂b = b − α · (1/m) · Σᵢ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾) w ← w_temp ← mise à jour ensemble APRÈS avoir calculé les deux b ← b_temp JAMAIS : w ← nouveau_w, puis utiliser ce nouveau w pour calculer ∂J/∂b car cela minimiserait une fonction différente de J

Le taux d'apprentissage α

α trop grand

Le pas dépasse le minimum → J oscille et diverge. Le modèle ne converge jamais.

α trop petit

Convergence très lente → des milliers d'itérations pour un résultat médiocre.

α optimal ✓

J décroît régulièrement et converge en ~100–1000 itérations. Valeurs typiques : 0.001 à 0.1.

Section 06

Régression Linéaire Multiple

En régression simple, une seule variable x explique y. En régression multiple, n variables expliquent y simultanément. Le raisonnement reste identique — seul le nombre de paramètres change.

Le modèle généralisé

Hypothèse — n variables explicatives ŷ = θ₀ + θ₁·x₁ + θ₂·x₂ + … + θₙ·xₙ θ₀ = biais (remplace b) θⱼ = coefficient de la feature xⱼ (remplace w quand n=1) n + 1 paramètres à apprendre : θ₀, θ₁, …, θₙ Forme vectorielle compacte : ŷ = θᵀ · x (avec x₀ = 1 pour absorber le biais θ₀)

Règle universelle des gradients

Pour tout θⱼ (j = 0 à n) : ∂J/∂θⱼ = (1/m) · Σᵢ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾) · xⱼ⁽ⁱ⁾, avec x₀⁽ⁱ⁾ = 1. Cette structure est universelle — elle s'applique quel que soit n.

Section 07

Feature Scaling — Mise à l'échelle

Quand les features ont des ordres de grandeur très différents, la descente de gradient converge lentement et de façon irrégulière. Le scaling corrige ce problème.

Le problème sans scaling

Exemple de déséquilibre d'échelle x₁ = surface ∈ [40 ; 130] m² → θ₁ doit être ≈ 1.85 x₂ = prix au m² ∈ [1000 ; 5000] €/m² → θ₂ doit être ≈ 0.0004 Le gradient ∂J/∂θ₂ est énorme (x₂ très grands) Les courbes de niveau de J forment une ellipse très allongée La descente oscille → beaucoup plus d'itérations pour converger

Deux techniques de scaling

Normalisation min-max
x' = (x − min) / (max − min)

Résultat : x' ∈ [0, 1]. Préserve la distribution. Sensible aux outliers.

Standardisation (z-score) ★
x' = (x − μ) / σ

Résultat : μ' = 0, σ' = 1. Robuste aux outliers. Recommandée en général.

⚠️ Règle critique — data leakage

Calculer μ et σ uniquement sur les données d'entraînement, puis appliquer ces mêmes valeurs au test. Ne jamais utiliser les données de test pour calculer les statistiques de scaling — cela constituerait une fuite d'information qui fausserait l'évaluation.

Section 08

Introduction à la Classification

Contrairement à la régression (prédire un nombre), la classification prédit à quelle catégorie discrète appartient un exemple.

Régression vs Classification

CaractéristiqueRégressionClassification
Sortie yValeur réelle continue ∈ ℝCatégorie discrète ∈ {0,1,2…}
ExemplePrix maison (275 k€)Transaction frauduleuse (1) ou non (0)
MétriqueMSE, RMSE, R²Accuracy, Précision, Rappel, AUC
ModèleRégression linéaireRégression logistique, Arbre, SVM…
Sortie du modèleŷ ∈ ℝ (un nombre)P(y=1|x) ∈ (0,1) → décision

Pourquoi la régression linéaire échoue pour classifier

Intuitivement, on pourrait utiliser la régression linéaire et seuiller à 0.5. Mais cela pose trois problèmes fondamentaux :

Sorties non bornées

ŷ peut valoir −0.3 ou 1.8. Impossible à interpréter comme une probabilité.

Points extrêmes

Un seul cas aberrant déplace toute la droite et reclasse mal les autres exemples.

Mauvaise pénalisation

La MSE pénalise de la même façon une petite et une grande erreur de classification.

Solution : on a besoin d'une sortie bornée entre 0 et 1, interprétable comme une probabilité, et robuste aux valeurs extrêmes → c'est le rôle de la fonction sigmoïde.

Types de classification

Binaire (2 classes)
y ∈ { 0 , 1 }

Spam/non-spam, maladie/sain, fraude/légitime. La plupart des algorithmes sont conçus pour ce cas.

Multi-classes (C classes)
y ∈ { 0, 1, …, C−1 }

Chiffre manuscrit (0–9), type de tumeur, espèce animale. On étend les modèles binaires via OvA ou Softmax.

Section 09

Régression Logistique — Le Modèle

La régression logistique résout la classification binaire en deux étapes : d'abord une combinaison linéaire (comme la régression), puis la fonction sigmoïde pour borner le résultat entre 0 et 1.

La fonction sigmoïde σ(z)

Définition de la sigmoïde σ(z) = 1 / (1 + e−z) Propriétés fondamentales : z → +∞ → e−z → 0 → σ(z) → 1 z = 0 → e⁰ = 1 → σ(0) = 0.5 exactement z → −∞ → e−z → +∞ → σ(z) → 0 Résultat : σ(z) ∈ (0, 1) pour tout z ∈ ℝ → probabilité valide

Le modèle complet

Régression logistique — 2 étapes Étape 1 — Combinaison linéaire (logit) : z = θ₀ + θ₁·x₁ + … + θₙ·xₙ = θᵀx Étape 2 — Application de la sigmoïde : hθ(x) = σ(z) = 1 / (1 + e−θᵀx) Interprétation : hθ(x) = P(y = 1 | x ; θ) Décision finale : ŷ = 1 si hθ(x) ≥ 0.5 (z ≥ 0) ŷ = 0 si hθ(x) < 0.5 (z < 0)

Exemple numérique — diagnostic diabète

Modèle appris : θ₀ = −8, θ₁ = 4 (glycémie), θ₂ = 0.2 (IMC) Patient A : glycémie = 1.2 g/L, IMC = 24 z = −8 + 4×1.2 + 0.2×24 = −8 + 4.8 + 4.8 = +1.6 σ(1.6) = 1/(1+e−1.6) = 1/(1+0.202) = 0.832 → 83.2% de probabilité de diabète → ŷ = 1 (diabétique) Patient B : glycémie = 0.8 g/L, IMC = 20 z = −8 + 4×0.8 + 0.2×20 = −8 + 3.2 + 4.0 = −0.8 σ(−0.8) = 1/(1+e0.8) = 1/(1+2.225) = 0.310 → 31% de probabilité de diabète → ŷ = 0 (non diabétique)
Interprétation des poids θ

θ₁ = 4 (positif) → quand la glycémie augmente, la probabilité de diabète augmente. θ₁ = −3 (négatif) → l'inverse. θ₁ ≈ 0 → cette feature n'influence pas la décision. Cette interprétabilité est une force majeure de la régression logistique.

Section 10

Fonction de coût — Log Loss & Entraînement

On ne peut pas utiliser la MSE avec la sigmoïde (la fonction résultante n'est plus convexe, elle a des minima locaux). On utilise la Log Loss (entropie croisée binaire).

Intuition : pénaliser les erreurs confiantes

Log Loss — formule unifiée J(θ) = −(1/m) · Σᵢ [ y⁽ⁱ⁾·log(hθ(x⁽ⁱ⁾)) + (1−y⁽ⁱ⁾)·log(1−hθ(x⁽ⁱ⁾)) ] Cas y = 1 (vrai positif) : coût = −log(hθ(x)) Si hθ = 0.99 → coût = −log(0.99) ≈ 0.01 ← correct et confiant, peu pénalisé Si hθ = 0.01 → coût = −log(0.01) ≈ 4.60 ← faux et confiant, fortement pénalisé Cas y = 0 (vrai négatif) : coût = −log(1 − hθ(x)) Si hθ = 0.01 → coût ≈ 0.01 ← correct ✓ Si hθ = 0.99 → coût ≈ 4.60 ← faux ✗

Gradient de la Log Loss

Gradient — même forme qu'en régression linéaire ! ∂J/∂θⱼ = (1/m) · Σᵢ ( hθ(x⁽ⁱ⁾) − y⁽ⁱ⁾ ) · xⱼ⁽ⁱ⁾ Mise à jour : θⱼ ← θⱼ − α · ∂J/∂θⱼ (même règle qu'en régression) Bonne nouvelle : la même structure de gradient s'applique. Seule hθ change : sigmoïde au lieu de linéaire.

Frontière de Décision Interactive

La frontière de décision sépare l'espace des features en deux régions : celle où le modèle prédit la classe 1 (hθ(x) ≥ 0.5, c'est-à-dire θᵀx ≥ 0) et celle où il prédit la classe 0.

Équation de la frontière de décision hθ(x) = 0.5 ↔ σ(θᵀx) = 0.5 ↔ θᵀx = 0 → θ₀ + θ₁·x₁ + θ₂·x₂ = 0 C'est une droite en 2D, un plan en 3D, un hyperplan en nD. D'un côté (θᵀx > 0) : Classe 1 De l'autre (θᵀx < 0) : Classe 0

Section 12

Arbres de Décision

Les arbres de décision apprennent une suite de règles hierarchiques qui partitionnent l'espace des features. Très interprétables, ils constituent la base des forêts aléatoires.

Algorithme CART — Comment l'arbre est construit

Critère de division — Indice de Gini Gini(t) = 1 − Σₖ pₖ² Nœud pur (une seule classe) : Gini = 1 − 1² = 0 (minimum, idéal) Nœud impure (50/50) : Gini = 1 − (0.5² + 0.5²) = 0.5 (maximum) À chaque nœud, CART cherche la coupure (xⱼ ≤ t) qui minimise : Gini_split = (nₗ/n)·Gini(tₗ) + (nᵣ/n)·Gini(tᵣ) On répète récursivement jusqu'à l'arrêt (profondeur max, nœud pur, etc.)

⚠️ Risque d'overfitting

Un arbre sans contrainte de profondeur peut créer une règle spécifique pour chaque exemple → 100% sur le train, très mauvais sur le test. Solution : limiter la profondeur, ou utiliser des ensembles d'arbres (Random Forest, Boosting).

Section 13

Forêts Aléatoires & Méthodes d'Ensemble

Les méthodes d'ensemble combinent plusieurs modèles pour obtenir de meilleures performances qu'un seul modèle. C'est le principe de la sagesse des foules.

Bagging — Bootstrap Aggregating

Principe du Bagging 1. Générer T sous-ensembles D₁, D₂, …, Dₜ par tirage avec remise 2. Entraîner un modèle hₜ(x) indépendamment sur chaque Dₜ 3. Agréger : Classification → Vote majoritaire : ŷ = mode(h₁(x), …, hₜ(x)) Régression → Moyenne : ŷ = (1/T) · Σₜ hₜ(x) Objectif : réduire la variance d'un modèle instable Les arbres profonds sont instables → excellents candidats pour le Bagging

Random Forest = Bagging + randomisation des features

À chaque nœud de chaque arbre, on ne considère qu'un sous-ensemble aléatoire de features (typiquement √n features). Ce double niveau de randomisation force la diversité entre les arbres → des erreurs différentes qui s'annulent à l'agrégation → performances supérieures.

Boosting — apprentissage séquentiel

Gradient Boosting Initialiser : f₀(x) = constante (ex : moyenne de y) Pour m = 1 à M : 1. Calculer les résidus : rᵢ = y⁽ⁱ⁾ − fₘ₋₁(x⁽ⁱ⁾) 2. Entraîner un arbre hₘ(x) sur les résidus rᵢ 3. Mettre à jour : fₘ(x) = fₘ₋₁(x) + η · hₘ(x) η (learning rate) ∈ (0, 1] : plus η est petit, plus chaque arbre contribue peu → apprentissage lent mais robuste (moins d'overfitting) Objectif : réduire le biais (contrairement au Bagging qui réduit la variance)

Section 15

Overfitting, Underfitting & Régularisation

Ces deux concepts décrivent les deux façons dont un modèle peut « mal apprendre ».

Le dilemme Biais — Variance

Décomposition de l'erreur de généralisation Erreur totale = Biais² + Variance + Bruit irréductible Biais = hypothèses trop rigides → underfitting Ex : modèle linéaire sur données quadratiques Symptôme : mauvais sur TRAIN et sur TEST Variance = sensibilité aux fluctuations du training → overfitting Ex : arbre de décision profond sans contrainte Symptôme : excellent sur TRAIN, mauvais sur TEST
